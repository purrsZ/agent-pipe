# 需求批阅台 · 交互原型 UX 走查结论

> 6 个用户人格对 `prototype-req-flow.html`（v1 单文件原型）做对抗式走查，共 **53 条 finding（6 阻塞 + 17 高 + 26 中 + 4 低）**。本文按主题归并 + 处置，驱动 v2 多文件原型（`prototype/` 目录）。
> 人格：首次/久未登录者、灯②审设计者、并行盯梢者、异常/取消者、飞书/手机用户、多需求切换者。

## 6 条阻塞（必修，v2 已处理）

| # | 人格 | 问题 | 处置 |
|---|---|---|---|
| B1 | first-glance | **默认落地是单需求工作台（写死优惠券改版），不是看板全景** —— 久未登录被空降进某件需求内部，看不到一共几件等你、哪件最急 | v2 默认落地 = **看板**（`index.html`），全景优先 + 等你项置顶 |
| B2 | exception | **打回不可逆**：无二次确认、无撤销、理由可空，而打回会触发整端回退重走 | v2 打回理由**必填**、提交后 **10s 撤销浮条** + 二次确认带后果（"本灯第 N 次打回"） |
| B3 | exception | **无 /cancel 入口 + 确认卡**（R21 要求）—— 工作台号称主战场却找不到取消，不知分支保不保留 | v2 工作台加克制的"取消需求"入口 → 确认卡**当场列明**：中止 N 工人、feat 分支**保留**、worktree 回收、半成品入收尾 journal |
| B4 | exception | **破坏性契约大改卡缺失** —— 被退化成和"传分还是元"一样的轻量二选一，诱导轻率拍板会触发返工 | v2 新增**大改卡**（标红"破坏性·会触发返工"）+ 三动作显式后果（准改→X/Y 端返工·其余照跑 / 不改→提出方撤回 / 再想→相关端暂停等你）+ 谁发现/为何/影响哪端/哪些活返工 |
| B5 | multi-req | **审设计页硬编码"商品收藏"** —— 从优惠券工作台点"对接合同"跳进另一个需求的接口清单（串台） | v2 审设计页**按 reqId 参数化**（标题/合同/质疑随需求渲染）+ 顶部面包屑"你在看：X / 对接合同" |
| B6 | (同 B5) | 多需求并存时内容串台、返回回错地方 | v2 面包屑 + 记来路返回 |

## 高频主题（归并 17 高 + 26 中）

### 主题一：统一"等你队列"（最高频，跨 4 人格）
- **病灶**：系统有多种"等你"——灯关卡（审设计待批）、焦点卡取舍（传分/元）、藏在工人面板的"UI 待你调"、契约大改卡——但① 计数口径打架（backlink "2 件" vs 看板 "1 处" vs 焦点卡）② 焦点卡只能显示一处、没有多处排队 ③ "UI 待你调"只在工人面板一行朱红字、不进焦点卡/不进计数 → 必然漏。
- **v2 处置**：① 统一 **open-wait 队列**为唯一真相源，所有计数（看板徽标/工作台/顶栏铃铛）共用同一来源、永远一致；② 焦点卡区改成**可堆叠的"等你队列"**（"该你拍·共 N 处"，按急缓排序，逐张消解，处理完顶上下一张）；③ 顶栏常驻**铃铛**列跨需求全部待办，点击直达、不强制离开当前需求。

### 主题二：两类"等你"严重度分级
- **病灶**：阻塞性关卡（灯，不处理则整件停）与非阻塞中途取舍（其余照跑）同色同权重（都朱红+脉冲），分不清谁该先处理。
- **v2 处置**：阻塞关卡用最高优先级（朱印 + "关卡·不处理则停"）；非阻塞取舍降一档（琥珀 + "不急·其余照跑"）；看板/工作台共用同一套分级色板。

### 主题三：灯②快慢两拍真正拆两步
- **病灶**：审设计页把快拍接口合同 + 慢拍详设质疑 + 慢拍才解锁的"通过"全平铺一屏，两拍只剩两个不可点标签 → 用户在"快拍·定方向"就被要求裁慢拍质疑、否则点不了通过，节奏坍塌成一锅烩。
- **v2 处置**：拆**两个页面步骤** —— 快拍页只放大纲 + 接口清单 + "确认接口·冻结发令"（解锁只看接口全勾），点完即发令；慢拍页才出现详设逐块 + 唱反调质疑 + "通过"。

### 主题四：解锁卡壳与批量
- **通过按钮双条件耦合卡壳**（质疑全裁∧接口全勾，缺口在隔半屏的接口区）→ v2 **缺口指引**（点灰按钮高亮滚动到第一个未完成项）+ 分区进度小计（"接口 0/4 ✓"）+ vb-status 缺口做成锚链接。
- **接口逐条勾无批量**（20 条要点 20 次）→ v2 **批量确认**（全部确认 / 按仓批量）+ 按提供方分组折叠 + 进度计数 + 有质疑牵连的接口强制单独二次确认。
- **质疑裁决无批量 + 撤销藏太深**（小字下划线）→ v2 "把剩余全部驳回（已覆盖）"批量（阻塞级质疑强制单独裁）+ 撤销提权为同级"改判↺"按钮 + 最近操作回执。
- **发令枪无二次确认**（通过=4 工人开跑，高后果单击即发）→ v2 通过前轻确认"将冻结合同并发令 N 工人并行，确认？"。

### 主题五：飞书侧完全缺失（飞书是主战场）
- **病灶**：v1 三视图全是网页，飞书锚点卡/灯交互卡/流式卡 mock 一屏都没有 → 设计承诺的"飞书拍板"从未被走查。
- **v2 处置**：新增 **`feishu.html`** 飞书 mock 分屏（手机宽度）：锚点卡（4 灯 rail + 工人 1/4 + 台账折叠）、灯②交互卡（4 按钮）、worker 流式卡；并体现：
  - **异步三态**（R06 3 秒 toast + 异步）：点击→"已收到·处理中"（按钮转圈）→成功翻已拍板态 / 失败"未成功·点此重试"（不再瞬时假完成 → 防重复点击两端打架）；
  - **轻拍板飞书闭环、重操作只通知跳网页**：标清哪些灯飞书可闭环（灯①/③/④/小改）、哪些只通知（灯②慢拍重操作）；
  - **流式卡静默更新**（updateCard 不触发通知/不置顶），只"要人卡"才 @ + 响铃（防 4 工人刷屏轰炸）；
  - **锚点卡被淹没**的解法：原地 updateCard 同一张 + 要拍板时重新顶一张轻量灯卡 @ 你。

### 主题六：进度可读性与异常呈现
- **工人进度看不出假活/真卡**（百分比来源不明、无最近活动时间）→ v2 每行补**最近活动时间**（"2 分钟前还在动"，对应 onActivity 活体探测）+ 步骤 x/N + 超阈值无心跳标黄 + 完成行挂产出链接。
- **工人举手"病历"态缺失**（R20/§5.8）→ v2 新增**病历卡**：该行变红展开"卡在哪/已试 N 次/失败根因（断言红 vs 测试跑不起来）"+ 1-2 个轻救场动作（补测试命令/跳过该端自测/打回重拆）。
- **自治留痕点不开**（"已自治 N 次"静态文本）→ v2 做成**可展开**（每次自治：改了哪条接口/前后 diff/影响哪端/可一键退回）+ 决策台账新增**"系统替我做的"分区**（与人拍的板并列、可退回）。
- **连拒 2 次升级对话无感知/过渡** → v2 打回卡显示"本灯已打回 N 次，再拒 1 次转对话深聊"+ 升级时活动流给过渡文案。

### 主题七：多需求与全局
- **排队卡信息黑洞**（"排队中"只 toast）→ v2 排队卡展开：排第几/谁占坑（可点过去）/何时轮到/可申请提优先级；"并行上限 3"改人话。
- **返回回错地方** → v2 面包屑 + 记来路。
- **顶栏身份/时间锚点缺失** → v2 顶栏 whoami（"上次登录 X 天前 · 这期间新增 N 件等你"）+ 久未登录时间戳改**绝对日期**。
- **跨需求决策总账缺失** → v2 看板/顶栏入口"我的决策总账"（按时间/需求/类型筛选）；修台账数据归属（只显本需求）。
- **介入条无回执**（"@包工头"发完只 toast，不知何时生效）→ v2 发送后活动流留痕"你·补充 X（待包工头下次唤醒采纳·不打断当前工人）"+ 明确生效时机。
- **看板 mini-rail 圆点无标签** → v2 当前点加阶段名 + "下一次需要你：审设计（现在）/验收（约 2 步后）/暂不需要"。
- **手机端表格/mermaid 溢出** → v2 窄屏宽表转卡片纵堆、mermaid 后端预渲染或降级占位。

## v2 原型结构（拆多文件，不再挤单 HTML）
```
prototype/
  index.html        看板（默认落地）：等你全景 + 两类等你分级 + 排队详情 + whoami + 决策总账入口
  workitem.html     单需求工作台：等你队列 + 自治可展开 + 工人病历态/进度可读 + /cancel + 大改卡 + 介入回执
  review.html       审设计（按 reqId 参数化）：快慢两拍真拆两步 + 缺口指引 + 批量确认 + 质疑批量/撤销提权 + 发令二次确认
  feishu.html       飞书 mock：锚点卡/灯交互卡/流式卡 + 异步三态 + 闭环vs通知分级 + 流式静默
  shared.css        提取 v1 纸张朱批风 + 两类等你分级色板 + 病历/大改/排队/三态样式
  shared.js         统一 open-wait 队列(单一计数源) + 路由/面包屑 + 异步三态 + 撤销浮条
```

## 不在原型范围（留给实现/已在设计覆盖）
- 真实异步回调失败重试的后端时序（R06/R19 已设计，原型只演示三态视觉）。
- mermaid 后端预渲染、内网穿透（R17 外部契约）。
- 鉴权（R18，原型不演示登录）。

> v2 原型**仍是蓝本/沟通工具**，非生产代码；它把上面 6 阻塞 + 七大主题的交互**画出来给人评审**，落地以 R17/R18/R19 + 本结论为准。
